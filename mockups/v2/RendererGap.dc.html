What this design asks of Intaglio

Colour is forbidden from carrying meaning, so texture is the load-bearing channel — it is how missing, unauthorised, low-coverage and off-source are told apart. That makes one renderer capability critical rather than nice to have.

The finding

Intaglio can express hatching geometrically with clipped line grobs, so this design is implementable today. What it lacks is a compact, shared paint or pattern vocabulary: GraphicParams.fill is Option[Rgba].

At 2,300 textured marks, the measured geometric route misses both structural gates: 32,202 elements · 2,497,582 bytes. A shared-pattern control uses 2,305 · 296,925.

2 · Two separable proposals. Neither is automatically upstream.

A · Per-render theming

storyatlas4s only · no upstream change

This one is not an Intaglio problem at all. Intaglio's GraphicParams is already a per-grob value and Theme is already an injectable case class. The constants are ours:

private[intaglio] object Style
  val params: Either[GraphicsError, Params]
    rgba(120,120,120,1.0) · rgba(160,160,160,0.30)
    rgba(60,60,60,0.25) · Rgba.Black

A parameterless val in a package-private object, read internally by the lowerings. Drop the visibility modifier, make the literals fields, and thread style: Style.Params through the five public lowering entry points — the private helpers already take it.

Keep this separate from the pattern decision. Prototype it in StoryAtlas when runtime theming is actually required; move it upstream only if the consumer court shows a generally useful API boundary.

B · Pattern fills

conditional upstream candidate

A genuinely new concept — but unusually cheap for one, because three things already hold:

defsAlready emitted and already forward-referenced. Six atlas SVGs carry <defs> with a <clipPath>, and clip-path="url(#clip-0)" appears before the def that resolves it. Browsers and the XML suite accept it. deviceGraphicParams flows verbatim into DevicePrimitive — the device layer never destructures fill, so a new field needs zero changes there. compatibilityThe private primary constructor is not the whole boundary: case-class fromProduct and Mirror.ProductOf construction remain public. An arity change needs source and binary consumer courts; it is not presumed compatible.

Model it as a finite enum of parameterised recipes, not a free-form SVG string — that keeps illegal states unrepresentable and lets the raster backends synthesise the same texture:

enum FillPattern:
  case Hatch(angleDeg, spacing, lineWidth)
  case CrossHatch(angleDeg, spacing, lineWidth)
  case Rules(spacing, lineWidth)
  case Stipple(spacing, radius)

4 · Blast radius

Intaglio is a source pin you own, at 596b398, checked out clean locally. It is 0.1.0-SNAPSHOT, unpublished, with the compatibility baseline explicitly not established. Two other repos pin the same revision.

image4s 0 references to GraphicParams re-pin plus clean consumer court
scalafim 6 references across 3 files source and binary court required; arity is not presumed safe
storyatlas4s 23 references the consumer that wants the feature

The one real friction is toolchain skew — Intaglio is on Scala 3.4.2 and storyatlas4s is ahead of it, and that migration is already an open blocker on Intaglio's own release lane. Touching the renderer now entangles you with it.

5 · The workaround, and why it is prototype-only

Intaglio can already draw hatching geometrically today: hatch lines inside a group whose viewport sets Clip.On, which lowers to a real <clipPath>. The marks here are overwhelmingly axis-aligned rectangles, so a rect clip is enough.

Measured court: 2,300 marks × 10 segments yields 32,202 SVG elements and 2,497,582 serialised bytes, beyond the declared 10,000-element and 2 MiB gates. The shared-pattern control yields 2,305 and 296,925. Browser timings are machine diagnostics only.

Keep the geometric route as the working implementation and small-view fallback. Do not accept it as the default for a viewport at this measured scale.

The raster route — a texture bitmap through Grob.image — is a trap: the PNG encoder deliberately uses uncompressed stored DEFLATE blocks for JVM/JS byte-identity, so every payload is huge, there is no tiling, and it is resolution-dependent.

Recommendation

Use existing Intaglio geometry for the StoryAtlas prototype. For the admitted 2,300-mark production target, open a separate Intaglio design slice for a generic paint/pattern abstraction, with no story semantics. Land it only after backend laws plus source and binary consumer courts. Treat per-render theming as an independent consumer need. This plate is a design decision record, not production runtime proof.

The honest counter-argument

A pattern fill is the first vocabulary item that is a deferred, referenced resource rather than a self-contained numeric primitive. That sits slightly against Intaglio's stated commitment that backends are dumb interpreters resolved at a single point. If that commitment is load-bearing for you, the alternative is to accept a documented degradation to solid fill on the three raster backends — which is cheap, but should be a decision rather than an accident.
